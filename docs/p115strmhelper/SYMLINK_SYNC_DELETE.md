# STRM 软链接同步删除（V2 分支）

此 fork 在 V2 2.8.80 中实现 [issue #435](https://github.com/DDSRem-Dev/MoviePilot-Plugins/issues/435) 的文件系统软链接追踪。V3 未修改。

## 使用

1. 在 MoviePilot V2 的插件市场添加 `https://github.com/dahaox3/MoviePilot-Plugins`，选择此来源的 **115网盘STRM助手 2.8.80**。
2. 在“其他功能 → 同步删除”中配置每个本地挂载对应的三段映射：`Emby路径#MoviePilot路径#115网盘路径`。媒体库和原始 STRM 目录都要挂载到 MoviePilot，且各自配置映射。
3. 开启“启用同步删除”和“按 STRM 软链接目标逐文件删除”，保存后等待日志提示“STRM 路径索引就绪”。新开关默认关闭，关闭时仍走原来的同步删除流程。
4. 通过神医助手发送真实的 `deep.delete`。没有对应网盘整理记录时仍需启用既有的“强制删除文件”开关。

例如 `/media/电影/片名.strm` 指向 `/linshi/原名.strm`，目标会依据 `/linshi` 的配置映射，而不会按 `/media` 对应的网盘目录删除。相对链接、连续链接及重叠路径的最长前缀均支持。多个 Emby 前缀相同时，仅在索引能确认唯一 MoviePilot 位置时继续。

## 删除边界

- 只支持 Linux 本地文件系统路径及文件软链接；目录软链接、无法读取的目录、越界目标、断链、循环链接和等长歧义映射拒绝删除
- 先建立内存索引，并通过文件系统监控保留 10 分钟删除快照，解决 Emby 先删除 STRM、之后才发送通知的问题
- 文件计划在入队时冻结，执行前再次校验文件状态；排队期间重新生成或修改的 STRM 不删除
- 电影、整剧、季、单集及多版本事件均展开成精确文件计划，不使用 TMDB 查询扩大到其他版本或其他季
- 先核对对应本地软链接整理记录；与索引冲突时跳过；网盘整理记录只按精确目标路径匹配
- 在已映射网盘目录中列出同名媒体，只有唯一候选才删除；保留原后缀的 `name.mkv.strm` 可以区分不同格式，普通 `name.strm` 对应多个格式时不猜测
- 仅调用存储模块的单文件删除，不调用递归媒体目录清理；确认成功后才清理对应整理记录，不额外删除原始 STRM 或本地软链接
- 路径无法确认、索引未就绪、映射变更或监控停止时，即使已启用“强制删除文件”，也不回退为按显示目录删除
- 不获取 STRM 内 URL，不从任意外部链接推断删除目标；不会把缺失的路径伪装成已确认软链接

## 限制

索引不是持久化的文件历史：插件启动前已经删除的链接、错过监控的文件和超过 10 分钟的通知不能可靠追溯，应跳过处理。开启功能后应先确认索引就绪再删除；挂载必须支持本地文件监控，不保证网络文件系统的远端变更通知。

如果 Emby 或其他进程在通知前还同时删除了原始 STRM，软链接目标校验会拒绝删除。未刮削、文件名不一致、缺少映射或网盘模块返回失败时同样保留资源。

## 验证

`tests/test_mediasyncdel_strm_target.py` 在隔离临时目录中验证真实 Linux 文件监控、先删除链接再通知、混合目录、相对链接、失效快照、重复目标、存储失败及精确历史查询。存储对象使用测试替身，不会访问或删除真实网盘文件。

```bash
python -m unittest discover -s plugins.v2/p115strmhelper/tests -p test_mediasyncdel_strm_target.py -v
python .github/scripts/plugin_frontend.py --source-directory plugins.v2 --plugin p115strmhelper
```

前端产物由同版本前端构建，发布包保留 `dist/assets/remoteEntry.js`。回退时关闭新开关并安装原版本；已经完成的媒体删除不会随代码回退恢复。
